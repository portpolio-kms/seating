# 학급 자리배치 앱 — 1단계 설계 (명단 + 자리배치)

작성일: 2026-11-17

## 1. 배경과 목적

선생님이 이전에 만든 교우관계 분석 앱(`Desktop\안티그라비티`)에는 실제 학생 실명과 설문 원문이 코드(`sample_data.js`, `app.js`)에 들어 있어 배포할 수 없다. 그래서 **누구나 자기 반 명단을 넣어 쓸 수 있고, 학생 정보가 밖으로 나가지 않는 공개 웹앱**을 새로 만든다.

핵심 쓰임새: 교실 TV에서 학생들에게 **랜덤 자리 뽑기처럼 보이는** 자리배치를 하되, 실제로는 교사가 미리 정한 학생 쌍 조건(같이 앉으면 안 되는 쌍, 반드시 같이 앉아야 하는 쌍)을 지킨다. 학생들은 조건이 있다는 사실을 알아채지 못해야 한다.

전체 계획은 세 단계이며, 이 문서는 **1단계만** 다룬다.

1. **명단 + 자리배치** ← 이 문서
2. 교우관계 분석 (구글 설문 + 엑셀 업로드, 관계망, 상담용 보기)
3. 생활지도 기록 (ClassEye `E:\00 초등학교\11 바이브코딩\02 생활지도 기록\behavior-tracker`의 기능을 새 구조로 다시 작성)

1단계의 데이터 구조(학급, 학생, 저장소, 교사/교실 모드)는 2·3단계가 그대로 올라탈 토대이므로, 확장을 막는 결정을 하지 않는다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 교사가 학급 명단을 입력하고, 교실 배치(짝/모둠)를 설정하고, 학생 쌍 조건을 지정한다.
- 교실 화면에서 세 가지 연출(A 한 번에 공개, B 한 명씩 뽑기, C 카드 뒤집기) 중 교사가 매번 고른 방식으로 자리를 공개한다.
- 공개된 결과는 항상 모든 쌍 조건을 지킨다. "다시 뽑기"를 해도 마찬가지다.
- 모든 데이터는 교사 브라우저에만 저장된다.

**비목표 (1단계에서 하지 않음)**
- 교우관계 설문, 관계망, 상담 화면 (2단계)
- 생활지도 기록 (3단계)
- 서버, 로그인, 기기 간 자동 동기화 (백업 파일로 대신함)
- AI 호출
- 앞자리 고정이나 특정 구역 지정, '지난번 짝 반복 금지' 같은 쌍 조건 외의 규칙. 선생님이 쌍 조건 외에는 필요 없다고 확인했다. 다만 기록은 저장되므로 나중에 추가할 수는 있다.

**실패 조건 (동작은 해도 이러면 실패)**
- 교실 화면에 쌍 조건, "조건 위반 0건" 같은 문구, 조건 때문에 생긴 티 나는 패턴이 보인다.
- 학생 데이터가 어떤 경로로든 네트워크로 나간다 (분석 도구, 외부 API 포함).
- 저장소(GitHub)에 실제 학생 이름이 들어간다. 예시 데이터는 모두 가짜 이름만 쓴다.
- 조건을 다 지킬 수 없는데 조용히 조건을 어긴 결과를 보여 준다.

## 3. 제약

- **배포:** GitHub Pages (정적 호스팅). 서버 코드 없음.
- **기술:** Next.js(정적 내보내기 `output: 'export'`) + React + Tailwind CSS + TypeScript. ClassEye와 같은 계열이라 3단계 통합이 쉽다. ClassEye는 Next 16.4.3 / React 19.3 / Tailwind 4를 쓴다. 이 Next.js 버전은 기존 지식과 다른 부분이 있으므로, 만드는 사람은 `node_modules/next/dist/docs/`를 확인해야 한다. GitHub Pages는 하위 경로(`/<저장소이름>/`)로 서비스되므로 `basePath`를 설정해야 한다.
- **저장:** 브라우저 IndexedDB. 백업 파일(JSON) 내보내기와 가져오기를 제공한다.
- **사용 환경:** 교실 PC + 교실 TV(큰 화면, 멀리서 읽힘). 한국어 UI.
- **프로젝트 위치:** `E:\00 초등학교\11 바이브코딩\11 자리배치` (새 git 저장소)

## 4. 고려한 방법 (Approaches)

| 방법 | 장점 | 단점 |
|---|---|---|
| **Next.js 정적 사이트 (선택)** | ClassEye와 같은 기술이라 3단계 통합이 쉬움. 서버 기능이 없어서 데이터가 나갈 경로가 구조적으로 없음 | 초기 세팅이 무거움. Next 16 문서 확인 필요 |
| HTML 파일 하나 (기존 앱 방식) | 가장 단순함. 오프라인 실행 가능 | 2·3단계로 커지면 코드가 엉킴 (기존 앱이 2,000줄 단일 파일) |
| Vite + React | 가볍고 단순함 | ClassEye 통합 때 한 번 더 옮겨야 함 |

선생님이 기술 선택을 맡겨서 Next.js 정적 사이트로 정했고, 배포는 선생님 요청으로 Vercel이 아닌 GitHub Pages로 정했다.

## 5. 기능 설계

### 5.1 학급과 명단

- 한 브라우저에 **여러 학급**을 만들 수 있다. 학급 선택 메뉴를 둔다. *(제가 정한 부분: 전담교사처럼 여러 반을 맡는 경우를 고려함)*
- 학생 정보: 번호, 이름, 성별(선택 입력: 남/여/미입력).
- 입력 방법: 직접 입력, 또는 엑셀이나 구글 시트에서 복사한 표(번호 / 이름 / 성별)를 붙여 넣기.
- 같은 이름이 있으면 경고한다. 학생을 지우면 그 학생이 들어간 쌍 조건도 함께 지운다(확인 후).

### 5.2 교실 배치 설정

- **짝 모드:** 줄 수 × 분단 수 형태의 2인 책상 격자.
- **모둠 모드:** 모둠 수와 모둠 인원(4 또는 6)을 정하고, 모둠을 격자 형태로 놓는다.
- 사용하지 않는 자리를 끌 수 있다(학생 수가 홀수일 때, 교실 구조 때문에 빈 자리가 있을 때).
- 쓸 수 있는 자리 수가 학생 수보다 적으면 저장할 수 없게 막는다.
- 학급마다 배치 설정을 저장한다.

### 5.3 학생 쌍 조건 (교사 화면에서만)

| 조건 | 짝 모드 | 모둠 모드 |
|---|---|---|
| 짝 금지 | 같은 책상 불가 | 제한 없음 |
| 모둠 금지 | 같은 책상 불가 | 같은 모둠 불가 |
| 반드시 짝 | 같은 책상 | 같은 모둠 |
| 반드시 같은 모둠 | 제한 없음 | 같은 모둠 |

- '반드시 짝'은 한 학생당 최대 1명이다. 2명째를 지정하려 하면 설정 단계에서 막는다.
- **저장할 때 충돌을 검사한다.** 반드시 함께 묶인 학생들(연결된 무리) 안에 금지 쌍이 있거나, 묶인 무리가 모둠 인원보다 크면 이유와 함께 알려 준다.
- 우선순위: 쌍 조건(반드시 함께 / 금지)은 절대 지킨다. 남녀 짝 규칙은 가능한 만큼만 지킨다.

### 5.4 배치 계산 (화면과 분리된 순수 함수)

- 입력: 학생 목록, 배치 설정, 쌍 조건, 옵션(남녀 짝 규칙 켜짐/꺼짐), 난수 시드.
- 출력: 자리별 학생 배정, 또는 "불가능 + 이유".
- 방식: 반드시 함께인 학생들을 한 덩어리로 묶고 → 무작위로 섞어 배치하고 → 위반이 있으면 자리를 바꿔 고치고 → 일정 횟수 안에 해결하지 못하면 새로 섞어서 다시 시도한다. 그래도 실패하면 불가능으로 보고한다.
- **랜덤처럼 보여야 한다:** 조건을 지키는 배치들 가운데서 고르게 뽑혀야 한다. 같은 조건으로 여러 번 뽑았을 때, 반드시 짝인 학생들도 매번 다른 자리에 앉아야 한다.
- **남녀 짝 규칙** *(제가 정한 부분)*: 옵션이며 기본값은 꺼짐이다. 쌍 조건보다 우선순위가 낮다.
  - 짝 모드: 남녀 짝 수를 가능한 최댓값에 가깝게 만든다. 단, 어떤 남녀 조합으로 짝이 되는지와 자리는 매번 무작위로 정한다. 그래서 성별 구성은 비슷해도 결과는 매번 달라 보인다.
  - 모둠 모드: 각 모둠의 남녀 인원 차이를 최소로 맞춘다(예: 4인이면 2+2에 가깝게).
  - 성별을 입력하지 않은 학생은 이 규칙에서 빼고, 남은 자리에 무작위로 넣는다.
- 테스트로 검증할 것: 많이 반복해도(예: 1,000회) 쌍 조건 위반이 0건인지, 자리 분포가 한쪽으로 치우치지 않는지, 불가능한 조건을 정확히 불가능으로 판정하는지.

### 5.5 공개 연출 (교실 화면)

- 교사가 "뽑기" 화면에서 연출 방식 A, B, C 중 하나를 고르고 시작한다. 마지막에 고른 방식을 기억한다.
- **결과는 연출을 시작하기 전에 이미 계산된다.** 연출은 보여 주기일 뿐이다.
  - A 한 번에 공개: 이름이 2~3초 섞이다가 전체가 한꺼번에 멈춘다.
  - B 한 명씩 뽑기: 룰렛처럼 이름이 돌다가 한 명씩 자리에 앉는다. 속도 조절과 "나머지 바로 공개" 버튼이 있다.
  - C 카드 뒤집기: 자리마다 뒤집힌 카드가 있고, 누르면 그 자리 학생이 보인다. "모두 뒤집기" 버튼이 있다.
- 공개가 끝나면 "다시 뽑기"와 "이대로 확정" 버튼을 보여 준다. 다시 뽑기도 조건을 지킨다.
- 교실 화면에는 이름과 자리, 칠판 위치만 나온다. 큰 글씨로 멀리서도 읽혀야 한다.
- 배치가 불가능하면 교실 화면에서는 연출을 시작하지 않고, "설정을 확인해 주세요" 정도로만 보여 준다. 자세한 이유는 교사 화면에서만 보인다.

### 5.6 확정, 기록, 인쇄

- 확정한 배치는 날짜와 함께 학급별 기록으로 저장된다.
- 교사 화면에서 두 자리를 차례로 눌러 서로 바꿀 수 있다. 바꾼 결과가 쌍 조건을 어기면 경고한다(막지는 않음, 교사 판단 존중).
- 좌석표를 인쇄할 수 있다(칠판 쪽 / 교사 쪽 두 방향).
- 지난 배치 기록을 열어 보고 지울 수 있다.

### 5.7 교실 화면과 교사 화면

**두 화면 방식 (기본, 선생님 결정):** PPT 슬라이드쇼의 발표자 보기처럼 동작한다.
- 교사 PC 모니터에는 **교사 창**(조작과 확인)을, 교실 TV에는 **발표 창**(학생들이 보는 화면)을 띄운다.
- 교사 창에서 "발표 창 열기"를 누르면 새 창이 열린다. 교사가 그 창을 TV로 옮기고 전체 화면으로 바꾼다. 브라우저가 지원하면(Chrome의 화면 배치 권한) 두 번째 화면에 자동으로 전체 화면으로 띄운다. *(제가 정한 부분)*
- 두 창은 브라우저 안에서만 통신한다(BroadcastChannel). 네트워크를 쓰지 않는다.
- **발표 창에는 조작 버튼이 없다.** 연출 선택, 시작, 속도 조절, 다시 뽑기, 확정은 모두 교사 창에서 한다. 단, C(카드 뒤집기)는 학생이 TV 앞에서 누를 수 없을 수 있으므로 교사 창에서도 카드를 뒤집을 수 있게 한다. 발표 창을 터치나 클릭해서 뒤집는 것도 허용한다. 발표 창에서 할 수 있는 조작은 이것뿐이다.
- 교사 창에는 발표 창에 지금 무엇이 나오는지 작은 미리보기와, 쌍 조건 점검 결과("조건 위반 0건")가 함께 보인다.
- 발표 창이 쉬는 동안에는 대기 화면(학급 이름, 날짜, 확정된 좌석표 중 교사가 고른 것)을 보여 준다.

**한 화면 방식 (보조):** TV를 PC 화면 복제로 쓰거나 모니터가 하나뿐일 때를 위한 방식이다.
- 앱은 항상 **교실 화면으로 시작**한다. 교실 화면에서는 뽑기 시작, 연출 선택, 확정된 좌석표 보기만 할 수 있다.
- 교사 화면을 열 때 "지금 화면이 TV에 보일 수 있습니다" 경고를 띄우고, PIN 입력 숫자는 가린다.
- 확정은 PIN을 입력해야 할 수 있다. 다시 뽑기는 PIN 없이 할 수 있다. *(제가 정한 부분: 학생이 실수로 확정하는 것만 막으면 충분함)*

**공통 잠금:**
- 교사 화면(명단, 배치 설정, 쌍 조건, 기록, 백업)은 **교사가 정한 4자리 PIN**으로 연다. 처음 실행할 때 PIN을 정한다.
- 일정 시간(기본 5분) 아무 조작이 없으면 교사 화면이 잠긴다. 한 화면 방식에서는 공개 연출을 시작할 때도 잠긴다. 두 화면 방식에서는 연출 중에도 교사 창이 열려 있어야 하므로 잠기지 않는다.
- PIN은 원문이 아닌 해시로 저장한다. 이 잠금은 **학생이 지나가다 열어 보는 것을 막는 수준**이다. 브라우저 개발자 도구까지 막지는 않으며, 그렇다고 화면에 안내한다.
- PIN을 잊어버리면 "모든 데이터 지우고 새로 시작"만 가능하다. 그래서 백업을 권하는 안내를 둔다.

### 5.8 백업과 가져오기

- 학급 단위 또는 전체 데이터를 JSON 파일로 내보내고 가져온다(교실 PC ↔ 집 PC).
- 백업 파일에는 학생 이름과 쌍 조건이 들어 있으므로, 내보낼 때 "학생 정보가 들어 있으니 안전하게 보관하세요"라고 안내한다.
- 가져올 때 같은 학급이 이미 있으면 덮어쓸지, 새 학급으로 추가할지 묻는다.
- 백업 파일에는 형식 버전 번호를 넣어서, 2·3단계에서 데이터 구조가 바뀌어도 이전 백업을 읽을 수 있게 한다.

## 6. 개인정보 원칙 (모든 단계 공통)

- 네트워크 요청은 정적 파일(앱 자체)을 받는 것뿐이다. 분석 도구, 외부 폰트 서버, 외부 CDN을 쓰지 않는다. 폰트와 라이브러리는 앱에 함께 묶어 배포한다.
- 예시와 테스트 데이터는 가짜 이름만 쓴다.
- 교실 화면에는 쌍 조건과 관련된 어떤 정보도 나오지 않는다.

## 7. 만드는 사람에게 맡기는 부분

- 화면 디자인과 컴포넌트 구조, 상태 관리 방식
- IndexedDB를 다루는 방식(작은 래퍼 라이브러리를 쓸지 직접 짤지)
- 배치 계산의 구체적 알고리즘과 재시도 횟수(5.4의 검증 조건만 만족하면 됨)
- 연출 애니메이션의 세부 타이밍
- GitHub Actions 배포 워크플로 구성

## 8. 2·3단계를 위해 지금 지켜 둘 것

- 학생은 학급 안에서 바뀌지 않는 `id`를 가진다(이름이 바뀌어도 기록이 이어지도록).
- 교사/교실 모드 구분은 앱 전체에 적용되는 공통 장치로 만든다. 2단계 관계 분석과 3단계 생활지도 화면도 교사 화면 안에 들어간다.
- 저장소 구조와 백업 형식에 버전 번호를 둔다.
- 2단계에서 쓸 설문은 구글 시트 + Apps Script로 학급 명단에 맞춰 자동 생성한다. 확정된 12문항: 내 이름, 친구별 친밀도 1~5, 가장 친한 친구 최대 3명, 더 친해지고 싶은 친구 최대 3명, 쉬는 시간에 주로 같이 노는 친구, 어려울 때 도움을 청할 수 있는 친구, 쉬는 시간에 혼자 있을 때가 있다 1~5, 지금 함께 있기 힘든 친구와 이유(선택 응답), 요즘 나는 행복하다 1~5, 학교생활이 즐겁다 1~5, 우리 가족과 지내는 것이 행복하다 1~5, 선생님께 하고 싶은 말(선택 응답). 1단계에서는 만들지 않는다.
