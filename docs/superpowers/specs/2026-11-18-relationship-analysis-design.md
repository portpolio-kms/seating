# 학급 자리배치 앱 — 2단계 설계 (교우관계 분석)

작성일: 2026-11-18
선행: `docs/superpowers/specs/2026-11-17-seating-app-design.md` (1단계, 배포 완료: https://portpolio-kms.github.io/seating/)

## 1. 배경과 목적

선생님은 교우관계 정보를 **자리 정할 때, 상담할 때, 생활지도할 때** 자주 본다. 이전 앱(`Desktop\안티그라비티`)은 실제 학생 데이터가 코드에 들어 있어 배포할 수 없었다. 2단계에서는 같은 쓰임새를 1단계 앱 안에, **데이터가 교사 브라우저 밖으로 나가지 않는 방식**으로 만든다.

이전 앱에서 선생님이 실제로 쓴 화면은 **관계망 그래프, 위기 학생 레이더, 상담 카드**이다. 히트맵은 쓰지 않았다.

3단계(생활지도 기록, ClassEye 기능 재작성)는 이 문서 범위가 아니다. 다만 상담 카드는 3단계 기록이 나중에 들어올 자리를 남겨 둔다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 학급 명단으로 구글 설문을 자동으로 만드는 Apps Script를 앱이 생성한다.
- 구글 시트 응답을 CSV로 올리면 학급에 연결해 저장하고 분석한다.
- 교사 화면에 **관계망 그래프, 관심 학생 레이더, 상담 카드(교사용·학부모용)**를 만든다.
- 레이더에서 "함께 있기 힘든 친구" 지목을 보고 **쌍 조건 추가를 추천**한다. 실제 추가는 교사가 누른다.

**비목표**
- 호감도 히트맵
- 엑셀(.xlsx) 업로드 (CSV만 받음)
- 설문을 앱 안에서 직접 받기 (서버 필요)
- 학기 간 비교 화면 (데이터는 쌓아 두되, 비교 화면은 나중에)
- 자동 멘토 짝 배치 (1단계의 "랜덤처럼 보이게" 원칙과 충돌)
- AI 호출

**실패 조건**
- 교우관계 정보(점수, 지목, 응답 원문, 레이더 결과)가 교실 화면, 발표 창, 한 화면 모드 교실 화면 중 어디에라도 나온다.
- 학부모용 상담 보기·인쇄물에 **다른 학생 이름**이 나온다.
- 학부모용에 선생님이 체크하지 않은 **서술형 응답**이 나온다.
- 외부 네트워크 요청이 생긴다 (그래프 라이브러리도 앱에 묶어 배포).
- 저장소(GitHub)에 실제 학생 이름이나 실제 응답이 들어간다.

## 3. 제약

- 1단계 제약을 그대로 따른다: Next.js 16 정적 내보내기, GitHub Pages(basePath), IndexedDB, CSP(`connect-src 'self'` 등), 외부 리소스 금지, 한국어 UI, 가짜 이름만 쓰는 예시·테스트.
- 교우관계 화면은 모두 **교사 화면(PIN 잠금) 안**에만 둔다.
- 저장 형식이 바뀌므로 `SCHEMA_VERSION`을 2로 올리고, **버전 1 백업도 계속 읽을 수 있어야** 한다.
- 그래프 라이브러리(vis-network, 약 600KB)는 교사 화면의 관계망 탭에서만 동적으로 불러와 교실 화면 로딩에 영향이 없게 한다.

## 4. 고려한 방법 (Approaches)

**그래프**
| 방법 | 장점 | 단점 |
|---|---|---|
| **vis-network를 npm으로 묶어 배포 (선택)** | 이전 앱과 같은 사용감(물리 배치, 끌기, 확대). 학생 중심 재배치를 이전 방식대로 구현 가능 | 용량 증가 (교사 탭에서만 로드) |
| SVG 직접 그리기 + 배치 계산 라이브러리 | 가볍고 디자인 통일 | 끌기·확대·클릭을 직접 구현해야 해서 작업 큼 |

**설문 생성과 업로드**
| 방법 | 장점 | 단점 |
|---|---|---|
| **앱이 명단을 넣은 Apps Script를 생성, 결과는 CSV 업로드 (선택)** | 명단 입력 1번. 설문 형식이 고정되어 CSV 해석이 확실. 엑셀 라이브러리 불필요 | 교사가 스크립트를 붙여 넣고 실행하는 단계가 있음 |
| 고정 스크립트 + 명단을 시트에 붙여 넣기 | 스크립트가 하나로 고정 | 명단 이중 입력 |

선생님이 추천안(vis-network + 앱 생성 스크립트 + CSV)을 골랐다.

## 5. 기능 설계

### 5.1 설문 (선생님 확정 사항)

12문항. 8번이 1단계 논의 때와 달라졌다: 지목 수를 정확히 세기 위해 **명단에서 고르는 방식 + 이유 서술형**으로 바꿨다 (선생님 승인).

| # | 문항 | 형식 |
|---|---|---|
| 1 | 내 이름 | 드롭다운 (필수) |
| 2 | 친구별 친밀도 "이 친구와 함께 활동하면 어때요?" | 표 형식 1~5 (1 = 힘들어요 … 5 = 아주 좋아요) |
| 3 | 가장 친한 친구 | 명단 체크, 최대 3명 |
| 4 | 더 친해지고 싶은 친구 | 명단 체크, 최대 3명 |
| 5 | 쉬는 시간에 주로 같이 노는 친구 | 명단 체크 |
| 6 | 어려울 때 도움을 청할 수 있는 친구 | 명단 체크 |
| 7 | 쉬는 시간에 혼자 있을 때가 있다 | 1~5 |
| 8a | 지금 함께 있기 힘든 친구가 있다면 골라 주세요 | 명단 체크, 최대 3명, **선택 응답** |
| 8b | 그 이유 | 서술형, **선택 응답** |
| 9 | 요즘 나는 행복하다 | 1~5 |
| 10 | 학교생활이 즐겁다 | 1~5 |
| 11 | 우리 가족과 지내는 것이 행복하다 | 1~5 |
| 12 | 선생님께 하고 싶은 말이나 고민 | 서술형, 선택 응답 |

- 설문 첫 설명: "이 설문은 선생님만 봅니다. 솔직하게 답해 주세요." 수준의 안내.
- 학생 표시는 모든 문항에서 **"번호. 이름"** 형식 (동명이인 구분, CSV에서 학생을 정확히 찾기 위함).
- 2번 표 형식에는 본인 행도 포함될 수밖에 없다. 본인 행은 응답하지 않아도 되게(행 필수 아님) 하고, 앱은 본인에 대한 점수를 무시한다.

### 5.2 Apps Script 생성

- 교사 화면 새 탭 **"교우관계"** 안의 "설문 만들기"에서, 현재 학급 명단이 들어간 Apps Script 코드를 보여 주고 [복사] 버튼을 둔다.
- 화면에 따라 할 단계 안내: 새 구글 시트 → 확장 프로그램 → Apps Script → 붙여 넣기 → 실행 → 권한 허용 → 만들어진 설문 링크를 학생들에게 공유 → 응답 모이면 응답 시트를 CSV로 다운로드.
- 스크립트는 구글 설문을 만들고 응답이 그 시트로 모이게 연결한다. 설문 제목은 "학급 이름 + 날짜" 기본값.
- 스크립트 텍스트에는 학급 이름과 "번호. 이름" 목록만 들어간다. 쌍 조건이나 다른 데이터는 넣지 않는다.

### 5.3 CSV 업로드와 저장

- "교우관계" 탭에서 CSV 파일을 고르면 파싱해서 **미리보기**(응답 수, 응답 안 한 학생, 명단에 없는 이름, 중복 응답)를 보여 주고, [저장]을 누르면 그 학급의 **설문 결과 1건**으로 저장한다.
- 한 학급에 설문 결과가 여러 건 쌓일 수 있다 (학기별). 목록에서 **보고 있는 설문**을 고르고, 지울 수 있다. 저장할 때 이름(기본값 "YYYY년 M월 설문")을 정할 수 있다.
- 학생 매칭은 "번호. 이름" 라벨로 한다. 명단이 바뀌어 맞지 않는 라벨은 "명단에 없는 응답"으로 보여 주고 버린다.
- 같은 학생이 두 번 응답했으면 **마지막 응답**을 쓰고 미리보기에 알린다.
- 저장 후 명단이 바뀌어도 학생 `id`는 1단계에서 이름·번호를 고쳐도 유지되므로 결과는 그대로 이어진다. 저장 후 **삭제된 학생**의 데이터는 지우지 않고, 교사용 화면에서 "(삭제된 학생)"으로 표시하며, 그래프와 레이더에서는 빼고, 받은 평균 같은 지표 계산에는 그 학생이 준 점수를 계속 포함한다. *(제가 정한 부분)*
- 저장되는 내용은 학생별 응답의 정규화된 형태이다 (점수는 studentId 기준, 체크 문항은 studentId 목록). CSV 원본 텍스트는 저장하지 않는다.
- 저장 후 안내: "내려받은 CSV 파일에는 학생 응답이 들어 있어요. 업로드했으면 지워 주세요."

### 5.4 분석 지표 (설문 결과 1건 기준)

- **받은 평균**: 다른 학생들이 이 학생에게 준 2번 점수 평균 (본인·빈칸 제외).
- **서로 친함**: 두 학생이 서로 4점 이상.
- **한쪽만 좋아함**: 한쪽 4점 이상, 다른 쪽 2점 이하.
- **함께 있기 힘들다고 지목한 학생 / 지목받은 학생**: 8a 기준.
- **낮은 점수 비율**: 받은 점수 중 1~2점 비율.
- 3~6번(친한 친구, 친해지고 싶은 친구, 같이 노는 친구, 도움 청할 친구)은 상담 카드와 그래프 정보 패널에 보여 준다.

### 5.5 관심 학생 레이더 (선생님 확정 기준)

| 신호 | 높음 | 보통 |
|---|---|---|
| 자아 만족도 | 9번 1~2점 | 10번(학교생활) 1~2점 |
| 다른 학생들의 적대감 | 8a로 2명 이상에게 지목 | 8a로 1명에게 지목, 또는 지목 0명이어도 받은 점수 중 1~2점이 30% 이상 |

- 고립(서로 친함 0명, 7번 4~5점)은 경고로 띄우지 않고 상담 카드의 **참고 표시**로만 쓴다.
- 학생의 레이더 등급은 두 신호 중 **높은 쪽**이다. *(제가 정한 부분)*
- "1~2점 30% 이상" 규칙은 그 학생이 받은 점수가 **5개 이상**일 때만 적용한다 (응답이 적을 때 한두 명 때문에 걸리는 것을 막음). *(제가 정한 부분)*
- 레이더 목록: 높음 먼저, 같은 등급은 번호순. 각 줄에 이유를 짧게 쓰고, 이름을 누르면 상담 카드로 간다.
- 응답하지 않은 학생도 **적대감 신호(다른 학생 응답에서 계산)**는 판단해서 레이더에 올리고, "설문 미응답" 표시를 붙인다. 자아 만족도 신호는 판단하지 않는다. 미응답 학생 전체 목록도 따로 보여 준다. *(제가 정한 부분)*
- **쌍 조건 추천**: 8a 지목을 **순서 없는 두 학생 쌍** 단위로 묶어 하나만 추천한다 (A→B와 B→A 지목이 모두 있으면 "서로 지목"으로 표시). 버튼은 "짝 금지 추가 / 모둠 금지 추가 / 넘기기". 두 학생 사이에 **어떤 종류든** 조건이 이미 있으면 "이미 설정됨"으로 보여 주고 버튼을 숨긴다. 추가는 1단계 `canAddConstraint` 검사를 거치고, 거부되면 그 메시지를 보여 준다. 넘긴 추천은 그 설문 결과에 순서 없는 쌍으로 기억해 다시 띄우지 않는다. *(제가 정한 부분)*

### 5.6 관계망 그래프

- 노드: 학생 (응답 안 한 학생도 포함). 크기는 받은 평균, 레이더 높음/보통이면 색으로 구분.
- 선 필터: [서로 친함] (기본) / [4점 이상 전부] / [함께 있기 힘듦].
- 학생을 누르면 **그 학생 중심 재배치** (이전 앱 방식): 오른쪽 서로 친함, 아래 한쪽만 좋아함(어느 방향이든), 위쪽 함께 있기 힘듦(어느 방향이든) 또는 서로 2점 이하, 왼쪽 그 밖. 옆 패널에 그 학생 요약과 [상담 카드 열기]. [전체 보기]로 돌아온다.
- 끌어서 위치 조정 가능 (저장하지 않음).
- vis-network는 이 탭에서만 동적 import 한다. CSP를 지켜야 하므로 런타임에 eval이나 외부 리소스를 쓰지 않는 빌드인지 확인한다 (불가하면 만드는 사람이 보고).

### 5.7 상담 카드

**교사용 (상담 준비)**
- 받은 평균, 서로 친한 친구 수, 레이더 신호, 고립 참고 표시
- 서로 친함 / 한쪽만 좋아함(양방향) / 3~6번 응답 / 이 학생을 친한 친구로 고른 학생 — **이름 포함**
- 이 학생이 지목한 학생과 이 학생을 지목한 학생, 그리고 8b 이유 원문
- 본인 응답: 7, 9~11번 점수, 12번 서술형
- 관련 쌍 조건 목록과 최근 확정 자리 (1단계 데이터)
- 학생 선택(번호순 드롭다운, 이전/다음), 설문 결과 선택

**학부모용 (화면과 인쇄)**
- 교사용 화면의 [학부모 보기]로 전환하고, 같은 내용을 인쇄할 수 있다.
- **다른 학생 이름은 나오지 않는다.** 숫자만 보여 준다: 받은 평균, 서로 친한 친구 수, 같이 노는 친구 수, 도움 청할 친구 수.
- 지목 관련 정보(지목받은 수 포함)는 기본으로 숨긴다. *(제가 정한 부분: 다른 학생의 응답에서 나온 민감 정보라 학부모에게 바로 보이지 않게 함)* 교사가 "지목받은 수 포함"을 체크하면 숫자만 나온다.
- 본인 점수 응답(7, 9~11번)은 기본으로 보인다.
- **서술형 응답은 기본으로 숨긴다.** 학부모 보기에 넣을 수 있는 서술형은 **이 학생 본인이 쓴 것**뿐이다: 본인의 12번, 본인의 8b. 다른 학생이 이 학생에 대해 쓴 8b는 **어떤 경우에도** 학부모 보기에 넣을 수 없다 (누가 지목했는지 드러나므로). 교사가 항목마다 "학부모 보기에 포함"을 체크해야 나온다. 체크 상태는 학생·설문·항목별로 저장한다.
- 학부모 보기에 나오는 서술형 안의 **명단에 있는 학생 이름은 자동으로 "○○"로 가린다** (이름, "이름이", 성 뺀 이름 등 흔한 형태 포함). 교사용 화면에는 체크할 때 "학생 이름이 들어 있어요. 학부모 보기에서는 ○○로 가려져요" 안내를 띄운다. *(제가 정한 부분: "다른 학생 이름이 나오면 실패" 조건을 교사 판단에만 맡기지 않기 위함)*
- 3단계 이후 생활지도·칭찬 기록이 들어갈 자리를 둔다 (2단계에서는 표시하지 않음).

### 5.8 백업

- 설문 결과도 백업에 포함한다. 백업 형식 버전 2. 버전 1 백업은 설문 없이 그대로 가져온다.
- 학급을 지우면 그 학급의 설문 결과도 지운다.
- 백업 안내 문구에 "설문 응답도 들어 있어요"를 더한다.
- 가져오기 검증(1단계 최종 수정에서 만든 runtime validator)에 설문 결과 형식을 추가한다.
